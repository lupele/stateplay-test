# Reward Model 质量评测与验收

本规范适用于本地完整 Qwen3.5-9B LoRA 奖励模型的独立留出评测，以及第三阶段首批 56 个条件的 API／本地奖励对照。教师固定使用 gpt-6.1-sol，学生输出四个候选各自的 0～100 分。

## 自动质量要求

| 指标 | 验收要求 |
|---|---|
| 四分数 JSON 有效率 | ≥99% |
| 整体平均绝对误差 MAE | ≤15 分，15 分本身通过 |
| 全局 Spearman 相关性 | ≥0.70 |
| 有效候选对排序一致率 | ≥75% |
| 五类分别计算的 MAE | 每类均 ≤15 分，任何一类缺失不能通过 |

有效候选对限定为同一组内教师评分差至少 10 分的两个候选。五类分别为 normal、macro_success、macro_fail、result_win、result_lose。使用所有候选的分数计算全局 Spearman，避免将每组只有四个候选的相关性混同为全局统计。

RMSE、最佳候选选择准确率、每组 Spearman、分类偏差和置信区间作为辅助结果报告，不设额外硬性阈值。无效 JSON 必须计入失败率，不能填零伪装成有效预测。评估每组使用候选的规范顺序完成一次四分数预测；训练中的候选排列增强仍需保持标签与视频对应。

## 数据与选模

按来源／动作／时间相似组件划分训练、验证、测试，保持同来源组件的已有归属；不将训练集结果当作泛化验收。模型由验证集选择，再报告独立测试结果。比较不同数据量版本时，应同时报告各自完整测试集和共同样本上的配对比较，避免将测试集组成变化误当成模型能力变化。

## 人工质量要求

至少审核 100 个真实、不同、有代表性的候选视频，保存候选 ID、模型版本和复核记录；复核来源划分与局限、参考视频交换及动作交换结果。审核记录必须匹配当前奖励模型与来源审计。不得伪造审核，也不能以自动指标通过代替人工复核。

## 第三阶段运行控制

数值达标、人工审核、软件验收和用户启动授权是分别检查的条件。study_v1 的 plan/stage_C_control.json 当前设置 allow_start=false：B 完成后暂停，等待用户新计划。质量要求的修改不解除该暂停。
